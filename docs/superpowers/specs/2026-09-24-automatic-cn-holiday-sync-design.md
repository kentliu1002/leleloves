# 中国法定节假日自动同步设计

## 目标

系统每天自动同步国务院公布的中国法定节假日安排，同时导入放假日期和周末调休上学日。学校安排与政府安排不一致时，家长后台的手工设置优先，后续自动同步不得覆盖人工调整。

首次上线后立即补齐 2026 年安排，包括国庆节 `2026-10-01` 至 `2026-10-07` 以及 `2026-10-10` 调休上学日。现有手工设置继续保留。

## 数据来源

同步任务读取 `NateScarlet/holiday-cn` 提供的年度 JSON：

`https://raw.githubusercontent.com/NateScarlet/holiday-cn/master/{year}.json`

该项目每日抓取国务院公告，并为每年数据提供 `papers` 来源链接。同步前必须验证：

- `year` 与请求年份一致；
- `days` 为有效日期数组，且每项包含名称、日期和 `isOffDay`；
- `papers` 至少包含一个 HTTPS 的 `gov.cn` 链接；
- 日期全部属于目标年份。

任一验证失败时，本次同步失败并保留数据库中的上次成功数据，不删除、不覆盖现有安排。

## 数据模型

在 `holidays` 和 `workday_overrides` 增加以下字段：

- `source`: `manual` 或 `government`，现有数据默认迁移为 `manual`；
- `source_year`: 自动数据所属年份；
- `source_key`: 自动数据的稳定标识；
- `source_url`: 对应国务院通知地址；
- `is_disabled`: 自动记录被手工删除后设为 `true`；
- `synced_at`: 最近同步时间。

为自动记录的 `source_key` 建唯一索引，保证重复运行不会生成重复数据。

增加单行状态表 `calendar_sync_state`，保存最近成功时间、同步年份、来源链接和最后一次错误，供后台页面展示同步状态。

## 转换与冲突规则

年度 JSON 中：

- `isOffDay: true` 的相邻日期，如果节日名称相同，则合并为一个 `holidays` 起止区间；
- `isOffDay: false` 的日期写入 `workday_overrides`；
- 自动同步使用 upsert 更新同一 `source_key`，不会产生重复记录；
- 一次完整数据通过验证并写入成功后，才清理该年份已经不在新公告中的旧自动记录。

人工设置优先级如下：

1. 手工假期与自动假期日期重叠时，接口只返回手工假期；
2. 手工调休与自动调休日期相同时，接口只返回手工设置；
3. 删除手工记录时仍执行物理删除；
4. 删除自动记录时改为 `is_disabled: true`，后续同步保留禁用状态，不重新显示；
5. 用户需要恢复政府安排时，可以重新手工添加对应日期；该记录按手工设置处理。

现有 `/api/holidays` 和 `/api/workdays` 继续返回数组，微信小程序无需修改。

## 同步任务与接口

新增 `/api/calendar-sync`：

- `GET` 返回最近一次同步状态，不包含任何密钥；
- `POST` 仅接受 Vercel Cron 使用 `CRON_SECRET` 发起的请求；
- 每次同步当前年份和下一年份；下一年公告尚未发布或返回 404 时记录为“尚未公布”，不视为破坏性错误；
- Vercel Cron 每天北京时间凌晨 02:30 运行，即 UTC `18:30`。

同步逻辑位于独立模块，Cron 接口和测试共同调用，避免把解析与数据库操作混在路由中。

## 后台页面

假期和调休列表为每条记录显示“政府同步”或“手工设置”标识。假期设置页顶部显示最近成功同步时间和同步年份；同步失败时显示已有数据仍在使用，不影响作业与积分计算。

手工添加、删除的操作入口保持不变。

## 错误处理

- 网络失败、404、格式错误或来源不是 `gov.cn` 时，不修改现有日历数据；
- 当前年份失败时记录错误并返回失败状态；
- 下一年份尚未公布时跳过该年份，当前年份仍可成功；
- 数据库写入先 upsert 后清理旧自动记录，避免同步中断导致全部安排丢失；
- 同步失败写入 `calendar_sync_state.last_error`，成功后清空错误。

## 验证

自动测试覆盖：

1. 同节日连续休息日合并成正确区间；
2. `isOffDay: false` 转成调休上学日；
3. 重复同步不产生重复记录；
4. 手工记录覆盖重叠的自动记录；
5. 手工删除的自动记录不会被再次启用；
6. 非 `gov.cn` 来源和不完整数据被拒绝；
7. 外部数据源失败时保留现有数据。

上线验证包括：数据库迁移检查、2026 年完整同步、API 返回核对、后台页面核对，以及微信小程序历史与积分接口回归。
